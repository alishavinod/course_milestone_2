# C.3: slash commands

Do not start this spec until every rule in C.1 and C.2 passes.

Slash commands are `body` strings starting with `/`, sent to
`POST /api/channels/{id}/messages`.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `post_message(channel, author, body, parent_id=None)` | `/me`, `/shrug`, `//literal` |
| `set_topic(channel, user, topic)` | `/topic` |
| `archive_channel(channel, user, archived)` | `/archive` and `/unarchive` |

## Adds

| Function | What it does |
|---|---|
| `run_slash_command(channel, user, body)` | Handles a body starting with `/`, and returns the response or the text to post |

## Rules

### Commands that post a message

These return `201 {message}` like any other message.

3.1 **`/me`.** `/me waves` posts a message whose `body` is exactly `/me waves`. It is not stripped
    or changed.

3.2 **`/me` without text.** `/me` returns `400`.

3.3 **`/shrug` with text.** `/shrug ok` posts a message whose `body` is `ok ¯\_(ツ)_/¯`: the text,
    one space, then the emoticon, which has exactly one backslash.

3.4 **`/shrug` alone.** `/shrug` posts a message whose `body` is just `¯\_(ツ)_/¯`.

3.5 **`//literal`.** A body starting with `//` is not a command. `//literal` posts a message whose
    `body` is exactly `//literal`.

3.6 **Unknown command.** `/nope` returns `400`.

### Commands with a side effect

These return `201` (not `200`) with `message: null`.

3.7 **`/topic`.** `/topic new words` returns `{message: null, channel}` with the new topic.

3.8 **`/invite`.** `/invite @user` adds that user to the channel and returns
    `{message: null, invited_user: UserObj}`. The user then appears in
    `GET /api/channels/{id}/members`.

3.9 **`/archive`.** `/archive` by the workspace owner returns `{message: null, channel}` with
    `is_archived: true`. Posting a normal message afterwards returns `423`.

3.10 **`/unarchive`.** `/unarchive` by the workspace owner works on an archived channel (it does
     not get `423`). It returns `{message: null, channel}` with `is_archived: false`, and posting
     works again.

Every request must answer within 5 seconds.
