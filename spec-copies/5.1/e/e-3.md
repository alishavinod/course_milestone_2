# E.3: IRC channels and bridging

Do not start this spec until every rule in E.1 and E.2 passes.

## Tips

- **Write as the web does.** A `PRIVMSG` calls `post_message` and `emit_event`, so `event_id` stays
  dense with web messages.
- **Read as the web does.** The gateway checks the events table about every 100 ms and sends new
  `message.created` events to its joined clients. Then a message from any node reaches IRC, and
  this does not depend on any one HTTP node.
- Do not send a client its own `PRIVMSG` back.
- **Restart the gateway after each change.** An old process on port `6667` keeps serving old code, so
  add `6667` to the list of ports in the restart command.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `join_channel(...)` | IRC `JOIN` adds the user to the channel |
| `post_message(...)`, `emit_event(channel_id, type, payload)` | IRC `PRIVMSG` |

## Adds

| Function | What it does |
|---|---|
| `find_irc_channel(name)` | Finds the channel for `#{workspace-slug}/{channel-name}`, or nothing |
| `bridge_events()` | Sends new web messages to IRC clients in those channels |

## Rules

Channel `general` in workspace `acme` is `#acme/general` on IRC. The separator is a literal `/`.

3.1 **Join.** `JOIN #slug/name` gets `:<nick>!<user>@<host> JOIN #slug/name`, then `353` listing the
    nick, then `366`. A `332` or `331` may also be sent. As with `POST /api/channels/{id}/join`, the
    user becomes a channel member.

3.2 **Unknown channel.** `JOIN` of a channel that does not exist gets `403`. So does `#slug-name`,
    the hyphenated form of a real channel.

3.3 **IRC to web.** `PRIVMSG #slug/name :<body>` creates a message written by the token's user. It is
    listed by `GET /api/channels/{id}/messages`, and WebSocket subscribers on all three nodes get
    `message.created` for it.

3.4 **Mixed writers.** Messages sent at the same time from IRC and from the web share one `event_id`
    sequence, with no gaps and no repeats.

3.5 **Web to IRC.** A message posted on any node reaches IRC clients in that channel as
    `:<nick>!<user>@<host> PRIVMSG #slug/name :<body>`, where `<nick>` is the author's username.

3.6 **A killed HTTP node.** After one HTTP node gets `SIGKILL`, a connected IRC client stays
    connected, and messages still cross both ways between IRC and the other two nodes.
