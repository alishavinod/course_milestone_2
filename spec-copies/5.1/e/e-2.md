# E.2: IRC connection

Do not start this spec until every rule in E.1 passes.

## Tips

- **Run the gateway as its own process.** `/app/irc.py`, using `asyncio` streams, with its own saved
  PID in the `start.sh` loop so it restarts if it dies. It must not live inside an HTTP node, or
  killing that node takes IRC down too.
- **Lines end in `\r\n`.** Read a line at a time and match commands in any letter case.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| The token lookup inside `require_user(request)` | `PASS <token>` |
| The loop in `/app/start.sh` | Starts the gateway, and starts it again if it dies |

## Adds

| Function | What it does |
|---|---|
| `handle_client(reader, writer)` | One IRC connection: registers it and handles its commands |

## Rules

The gateway listens on `0.0.0.0:6667`. A client sends `PASS <token>`, `NICK <nick>` and
`USER <user> 0 * :<real name>`, where `<token>` is the bearer token from `/api/auth/login`.

2.1 **Registration.** A good `PASS` then `NICK` and `USER` gets the numerics `001`, `002`, `003`,
    `004`, `005`, then `422`, in that order.

2.2 **Bad password.** A `PASS` with an invalid token gets `464`.

2.3 **Nick in use.** A `NICK` already held by another connection gets `433`. The connection stays
    open, and a second `NICK` with a free name completes registration.

2.4 **Unknown command.** A command the gateway does not know gets `421`.

2.5 **Ping.** `PING <text>` gets a `PONG` line containing `<text>`.

2.6 **Accepted commands.** `PONG`, `NAMES`, `WHO`, `LIST`, `TOPIC` and `MODE` never get `421`.

2.7 **Quit.** `QUIT` closes the connection, with no numeric error and no `ERROR` line.
