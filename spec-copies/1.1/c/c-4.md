# C.4: user groups and mentions

Do not start this spec until every rule in C.1 to C.3 passes.

## Tips

- **`@here` must see all three nodes.** A user connected to `8001` counts when a message is posted
  on `8000`. Keep a `presence` table in the database with one row per open WebSocket: `(connection_id,
  user_id, seen)`. Add the row as soon as the WebSocket connects, commit it, update `seen` about once
  a second, and delete it on close. `@here` reads rows with a recent `seen` and keeps the channel's
  members. It depends on the connection, not on `subscribe`.
- A group handle can contain `-`, so the mention pattern must too.

## Objects

- `GroupObj`: `{id, handle, name, member_user_ids: [...]}`. Request bodies use `user_ids`.
  Responses use `member_user_ids`, never `members`.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `require_user(request)`, `get_workspace(slug)`, `get_role(workspace_id, user_id)` | The caller, the workspace, membership |
| `resolve_mentions(body, channel, author_id)` | Now also expands `@group-handle` and `@here` |

## Adds

| Function | What it does |
|---|---|
| `group_to_json(group)` | The `GroupObj` |
| `can_edit_group(group, user)` | True for the group's creator or the workspace owner |

## Rules

Never return `422`. Bad input is `400`. Check the token first: no valid token is `401`.

### Groups

4.1 **Create.** `POST /api/workspaces/{slug}/groups` with `{handle, name, user_ids}` by any
    workspace member returns `201 {group: GroupObj}`. `member_user_ids` holds the ids, and there
    is no `members` field. A user outside the workspace gets `403`. No token returns `401`.

4.2 **List.** `GET /api/workspaces/{slug}/groups` returns `200 {groups}` holding the group.

4.3 **Bad create.** A handle already used in the workspace returns `409`. A missing handle returns
    `400`. An unknown workspace returns `404`.

4.4 **Update.** `PATCH /api/workspaces/{slug}/groups/{handle}` with `{name, user_ids}` returns
    `200 {group}` with the new values, for the group's creator or the workspace owner. Any other
    member gets `403`.

4.5 **Delete.** `DELETE /api/workspaces/{slug}/groups/{handle}` returns `200 {"deleted": true}`
    for the creator or the workspace owner, and any other member gets `403`. Deleting it again
    also returns `200 {"deleted": true}`.

### Mentions

4.6 **`@group-handle`.** `mentions` holds the group's members who are also in the channel, without
    the author. A group member outside the channel is left out.

4.7 **`@here`.** `mentions` holds the channel's members with an open WebSocket on any node, without
    the author. A WebSocket counts as soon as it is open, even if it has not sent `subscribe`. A member with no
    open WebSocket is left out. After a member closes their WebSocket,
    a new `@here` leaves them out within 3 seconds.

4.8 **No repeats.** `@bob @group @here`, where Bob is in all of them, lists Bob once. His
    `mention_count` in `GET /api/channels/{id}/read` goes up by exactly 1.

4.9 **Never yourself.** An author in the group who writes `@me @group @here` is not in `mentions`,
    and their own `mention_count` does not change.

Every request must answer within 5 seconds.
