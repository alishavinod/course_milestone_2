# C.1: reactions and DMs

Do not start this spec until the basics it uses work: register, workspaces, joining channels,
posting and listing messages, and WebSocket events.

## Objects

- `reactions` on a `MessageObj` is `[{emoji, count, user_ids}]`.

## Uses

Call these functions from the earlier parts of the app. Do not write a second version of any of
them.

| Function | Used here for |
|---|---|
| `require_user(request)` | The caller of every route |
| `message_to_json(message)` | Now fills `reactions` |
| `emit_event(channel_id, type, payload)` | `reaction.added` and `reaction.removed` |

## Adds

Define these as separate Python functions with these names.

| Function | What it does |
|---|---|
| `add_reaction(message, user, emoji)` | Stores one reaction per (user, emoji) |
| `remove_reaction(message, user, emoji)` | Removes the caller's reaction |
| `get_or_create_dm(user_a, user_b)` | Returns the DM channel of two users, creating it once |

## Rules

Never return `422`. Bad input is `400`. Check the token first: no valid token is `401`.

### Reactions

1.1 **Add.** `POST /api/messages/{id}/reactions` with `{emoji}` returns `200` (not `201`) with
    `{reactions: [{emoji, count: 1, user_ids: [<caller>]}]}`.

1.2 **Once per user and emoji.** Adding the same emoji again returns `200` and `count` stays `1`.
    A second user adding it gives `count: 2` and both ids in `user_ids`.

1.3 **On the message.** `GET /api/channels/{id}/messages` shows the same `reactions` on the
    message.

1.4 **Remove.** `DELETE /api/messages/{id}/reactions/{emoji}` removes only the caller's reaction
    and returns `200 {reactions}`. The emoji in the URL is percent-encoded, so `👍` must work.

1.5 **Bad requests.** A missing `emoji` returns `400`. An unknown message returns `404`. No token
    returns `401`.

1.6 **Events.** Adding a reaction adds a `reaction.added` event, and removing one a
    `reaction.removed` event, on the channel's dense `event_id` sequence.

### DMs

1.7 **Open a DM.** `POST /api/dms` with `{user_id}` returns `200` (not `201`) with
    `{channel_id}`. A repeated call and the other user calling both return the same `channel_id`.

1.8 **Bad requests.** A missing `user_id` returns `400`. An unknown user returns `404`. No token
    returns `401`.

1.9 **Usable.** Both users can post to and list the DM channel.

Every request must answer within 5 seconds.
