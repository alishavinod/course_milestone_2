# C.2: files

Do not start this spec until every rule in C.1 passes.

## Tips

- FastAPI needs `python-multipart` for uploads. List it in `/app/requirements.txt`.
- All three nodes must be able to serve every file, so keep the bytes and details somewhere they
  all share.

## Objects

- `FileObj`: `{id, uploader_id, filename, content_type, size, created_at}`.
- `files` on a `MessageObj` is a list of `FileObj`.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `require_user(request)` | The caller of every route |
| `post_message(channel, author, body, parent_id=None)` | Attaching files to a new message |
| `message_to_json(message)` | Now fills `files` |

## Adds

| Function | What it does |
|---|---|
| `save_upload(upload, user)` | Stores the file, or answers `413` over 10 MiB |
| `file_to_json(file)` | The `FileObj` |
| `check_attachable(file_ids, user)` | Answers `400` unless every file is the user's own and not attached yet |

## Rules

Never return `422`. Bad input is `400`. Check the token first: no valid token is `401`.

2.1 **Upload.** `POST /api/files` as `multipart/form-data` with a `file` part returns
    `201 {file: FileObj}` with every field. `created_at` is a UTC timestamp.

2.2 **Details.** `GET /api/files/{id}` returns `200 {file}`. An unknown id returns `404`.

2.3 **Download.** `GET /api/files/{id}/download` returns the raw bytes, the matching
    `Content-Type`, and a `Content-Disposition` header containing the filename.

2.4 **Size limit.** A file of exactly 10 MiB (10485760 bytes) returns `201`. One byte more returns
    `413`.

2.5 **Bad uploads.** A request with no `file` part returns `400`. No token returns `401`.

2.6 **Attach.** `POST /api/channels/{id}/messages` with `{body, file_ids: [<id>]}` returns `201`
    and the message's `files` holds that `FileObj`.

2.7 **Attach rules.** `file_ids` with another user's file, or a file already attached to a message,
    returns `400`.

Every request must answer within 5 seconds, except the two uploads in rule 2.4, which have 10.
