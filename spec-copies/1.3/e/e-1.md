# E.1: message edit and delete

## Objects

- `MessageObj` has `edited_at`, which is `null` until the first edit.

## Uses

Call these functions from earlier parts of the app. Do not write a second version of any of them.

| Function | Used here for |
|---|---|
| `require_user(request)` | The caller |
| `get_role(workspace_id, user_id)` | Whether the caller owns the workspace |
| `message_to_json(message)` | The `message` object |
| `emit_event(channel_id, type, payload)` | `message.updated` and `message.deleted` |

## Adds

| Function | What it does |
|---|---|
| `edit_message(message, user, body)` | Saves the new body and sets `edited_at` |
| `delete_message(message, user)` | Marks the message deleted. Doing it twice is fine |

## Rules

Check the token first: no valid token is `401`. Never return `422`.

1.1 **Edit.** `PATCH /api/messages/{id}` with `{body}` by the author returns `200 {message}` with the
    new `body` and `edited_at` set to a timestamp. Every node shows the change.

1.2 **Who can edit.** Anyone but the author gets `403`, including the workspace owner. An unknown id
    returns `404`.

1.3 **Editing a deleted message** returns `409`.

1.4 **Delete.** `DELETE /api/messages/{id}` by the author or the workspace owner returns
    `200 {"deleted": true}`. Doing it again returns the same. Anyone else gets `403`.

1.5 **Gone from listings.** A deleted message is no longer in `GET /api/channels/{id}/messages`.

1.6 **Events.** An edit sends `{"type": "message.updated", "event_id", "channel_id", "message":
    MessageObj}`. A delete sends `{"type": "message.deleted", "event_id", "channel_id", "message_id"}`.
    Each adds exactly one event, and a repeated delete adds none.

Every request must answer within 5 seconds.
