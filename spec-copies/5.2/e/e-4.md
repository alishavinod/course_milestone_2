# E.4: web UI page and pinned hooks

Do not start this spec until every rule in E.1 to E.3 passes.

## Tips

- **Write it in pieces.** A single large file write can fail. Keep `static/index.html`,
  `static/style.css` and `static/app.js` separate, and add to `app.js` in several small steps.
- **Keep markup in the HTML file.** The hooks below must be in the HTML as served, not added by
  JavaScript. Hide what is not in use with the `hidden` attribute.
- **Colour by role.** `[data-button-role=primary] { background-color: #007a5a; color: #ffffff; }`
  and the same for the others. No gradients, images or transparency on these buttons.

## Uses

Nothing from earlier parts of the app.

## Adds

| Function | What it does |
|---|---|
| The `GET /` route | Serves `static/index.html` from every node |

## Rules

4.1 **The page.** `GET /` returns `200` with HTML on all three nodes.

4.2 **`data-testid` values.** The HTML as served has an element for each of these:

    `auth-form`, `auth-submit`, `auth-toggle`, `workspace-create-form`,
    `empty-state-create-workspace`, `join-workspace-form`, `join-workspace-submit`, `channel-list`,
    `dms-list`, `new-channel-btn`, `current-user`, `logout-btn`, `workspace-header`,
    `workspace-settings-btn`, `workspace-settings-close`, `workspace-name-input`,
    `workspace-join-mode`, `workspace-general-submit`, `channel-title`, `channel-topic`,
    `channel-settings-btn`, `channel-settings-title`, `channel-settings-close`,
    `channel-members-list`, `channel-add-member-form`, `channel-add-member-input`,
    `channel-add-member-submit`, `channel-topic-input`, `channel-topic-submit`,
    `archive-channel-btn`, `unarchive-channel-btn`, `create-channel-form`, `create-channel-private`,
    `create-channel-submit`, `create-channel-cancel`, `message-list`, `message-input`, `send-btn`,
    `thread-panel`, `thread-input`, `thread-send`, `close-thread`, `settings-tab-members`,
    `settings-tab-invitations`, `settings-tab-general`, `settings-pane-members`,
    `settings-pane-invitations`, `settings-pane-general`, `create-invitation-btn`,
    `create-invitation-form`, `create-invitation-submit`, `invitations-list`.

4.3 **DOM ids.** The HTML as served has the ids `auth-modal`, `create-channel-modal`,
    `channel-settings-modal`, `workspace-settings-modal` and `create-invitation-form`.

4.4 **Button roles.** In the HTML as served, these have `data-button-role` with this value:

    - `primary`: `auth-submit`, `send-btn`, `thread-send`, `create-channel-submit`,
      `join-workspace-submit`, `workspace-general-submit`, `create-invitation-submit`,
      `channel-topic-submit`, `channel-add-member-submit`.
    - `danger`: `archive-channel-btn`, `logout-btn`.
    - `secondary`: `new-channel-btn`, `create-invitation-btn`, `unarchive-channel-btn`,
      `create-channel-cancel`, `close-thread`, `channel-settings-close`,
      `workspace-settings-close`, `channel-settings-btn`, `workspace-settings-btn`.

4.5 **Button colours.** At 1280x900, not hovered, focused or disabled, each button's computed colours
    are exactly:

    | Role | `background-color` | `color` |
    |---|---|---|
    | `primary` | `rgb(0, 122, 90)` | `rgb(255, 255, 255)` |
    | `danger` | `rgb(224, 30, 90)` | `rgb(255, 255, 255)` |
    | `secondary` | `rgb(18, 100, 163)` | `rgb(255, 255, 255)` |
